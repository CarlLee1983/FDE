## 五部分 minimum operating solution

1. **營運問題與結果**

   目前僅有 20 筆經挑選工單的 demo 結果，其中 18 筆摘要「看起來不錯」。這可作為探索訊號，但不是 production 核准、30% 效益或正式權限的證據。
   範圍是客服工單處理中的「摘要供客服人員使用」步驟；決策是：是否進入有明確界線的驗證，而非是否上 production。所需結果是取得足以決定下一階段的可追溯證據。

2. **現況診斷**

   - 正常路徑：工單進入 → 人員閱讀內容 → 形成摘要 → 處理或轉派。
   - 例外路徑：摘要遺漏、錯置或不確定時，人員必須回讀原工單。
   - 升級路徑：涉及敏感資料、客訴風險、政策判斷或高影響案件時，須由具權責者判斷。
   - 重工路徑：錯誤摘要造成更正、重新分類、重新處理或回覆修正。

   目前缺少未挑選／具代表性的樣本、錯誤案例與門檻、正式使用者驗收、資安核准、production access、rollback owner，以及處理時間的基線與量測方法。因此不能將 demo 成果外推為已獲准或可節省 30%。

3. **技術中立的目標工作流程**

   工單進入後，先以既定欄位、分類規則與知識來源整理處理脈絡；產生任何摘要後，客服人員仍可檢視原始內容並對高風險、不確定或例外案件進行人工覆核。
   對錯誤、敏感資料及升級案件，流程必須有明確轉交條件、紀錄位置、停止使用條件與回復責任。先以代表性樣本驗證此流程，再決定是否引入或擴大自動化。

4. **介入方案與 AI-fit 決策**

   可比較的介入方式包括：

   - 以摘要模板、分類規則、知識內容整理與責任分派減少重工；
   - 以確定性軟體處理欄位擷取、路由、權限與政策檢查；
   - 以介面輔助讓人員更快閱讀、比對與更正；
   - 僅在保留「語意摘要」這項工作仍有價值時，使用 AI 作為有人員覆核的輔助。

   **決策：AI 不應直接進 production；先延後 AI 擴大採用，進行受控驗證。** demo 不足以證明價值、授權或安全性。驗證應使用事先定義的、較具代表性的樣本與錯誤／例外集，量測相對於既有流程的摘要品質、人工修正率、處理時間及高風險失誤；所有結果僅能支持其實際量測範圍內的結論。

5. **下一個可問責行動**

   由**客服營運的指定決策負責人**在下一個工作週期確認驗證 owner、樣本取得權限與成功／停止門檻；由資安權責者確認資料與存取評估需求；由使用者驗收負責人定義可接受的摘要品質與例外處理；並指定 rollback owner。
   可觀察的下一步產物是：一份具 owner、截止日、樣本來源、驗收門檻、例外處理、停止條件與回復責任的驗證計畫。完成這些工作前，不提出 production 核准或 30% 節省的主張。
