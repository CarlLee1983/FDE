## 產生的五部分 minimum operating solution

1. **營運問題與結果**
   使用者為提出低額辦公用品申請的員工、直屬主管及行政採購；位置在「申請送出後、行政採購前」的核准關卡。已知一年內小額逐筆主管審核未攔截違規、平均增加一天等待。下一個決策是：能否以明確規則取代常規逐筆核准，同時保留真正需要人類授權的例外。
   參考假設：現行目錄、額度與禁止品項規則能被可靠地套用；尚未證實主管核准是否承載預算、必要性、專案歸屬或其他未記錄的責任。

2. **現況診斷**
   正常路徑：員工申請 → 主管逐筆審核 → 行政採購。此關卡在已知資料下多屬等待與重複檢查，沒有顯示其降低政策違規風險。
   例外：非目錄、禁止品項、超額、資料不足或規則比對失敗的案件。
   升級：規則衝突、疑似拆單規避額度、供應商／安全／合規疑慮，送行政採購指定的控制所有人或財務／合規責任人。
   返工：退回申請人補齊品項、數量、用途或成本中心，再重新執行規則判定。
   缺口：沒有主管批准以外控制的證據，也沒有證據證明主管核准不承載其他授權；不得直接刪除關卡而宣稱風險不變。

3. **技術中立目標流程**
   先將小於 NT$3,000 的申請依既有目錄、額度、禁止品項做一致的規則檢核。全數通過者直接進行政採購；任一規則失敗、資訊不足或命中風險訊號者，保留結構化理由並送對應負責人。行政採購定期抽樣覆核直通案件與例外原因；明確記錄規則版本、輸入、結果、覆核與覆核人。若驗證主管不存在其他必須的授權，移除常規主管逐筆核准。

4. **介入與 AI 適配決策（含證據限制）**
   比較後選擇：
   - 流程／責任重分配：移除符合條件案件的主管逐筆核准，保留例外升級。
   - 資訊修復：使目錄、禁止品項、額度、成本中心與例外理由結構化。
   - 確定性軟體：用規則引擎進行金額與目錄／禁止品項判定。
   AI 不需要作為本輪決策引擎：已知判定規則明確，AI 自動「判斷並送主管」既未處理不必要控制，也會把穩定政策執行改成較難稽核的機率式判定。若日後自由文字品項描述難以對應目錄，AI 僅可提出分類建議；規則與人類負責人決定路由及任何持久性效果。

5. **下一個可問責行動**
   行政採購流程所有人應在兩週內，與財務／合規及代表性直屬主管完成「主管逐筆批准責任盤點」：逐項確認其是否承載預算、必要性、成本中心或其他未被規則覆蓋的授權，並簽核目標例外矩陣與抽樣覆核責任。驗收訊號為：有簽名／記錄的責任矩陣、可測試的規則集、例外擁有人，以及以目前平均一天等待為基線的試行週期時間與誤路由率。未完成盤點前，只能試行建議／預填與人工確認，不可啟用無人監督直通或撤銷主管權限。
