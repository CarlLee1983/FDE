## 圖表定義

圖表列出三類來源：業務系統資料（ERP、CRM、MES、IoT）、企業素材（文件、試算表、SOP 與專家經驗），以及外部領域知識（產業、政策、競爭者）。這些來源透過 API、資料檢視、檔案同步或 MCP 進入，在進入本體前會先被蒐集、清理與對齊。

## 擷取不只是匯入

目標不是集中儲存，而是取得可搭配可信業務意義使用的資料。每個來源都應從四個面向評估。

| 面向 | 關鍵問題 | 建議控制措施 |
| --- | --- | --- |
| 連接性 | 能否可靠地擷取？ | 定義同步模式、頻率、失敗重試與監控 |
| 語意 | 欄位或文件內容代表什麼？ | 將其對應至已定義的物件、關係與動作 |
| 品質 | 資料是否完整、正確且及時？ | 設定品質規則、例外佇列與可追責的負責人 |
| 存取 | 誰可讀取、編輯或將資料用於 AI？ | 對資料與本體資產套用最小權限存取 |

## 建議的擷取生命週期

```text
盤點來源 → 確認所有權與用途 → 連接與蒐集 → 清理／標準化
→ 對齊語意 → 驗證品質 → 發布本體資產 → 持續同步與審查
```

標準化通常包括代碼、時間戳記、單位、狀態值、組織名稱與鍵值。關鍵問題在於，一筆紀錄是否確實代表它所對應的本體物件或關係。

## 知識來源需要其自身的控制措施

| 來源類型 | 需要額外確認的資訊 |
| --- | --- |
| SOP 或政策文件 | 範圍、版本、生效日期、核准人與替代狀態 |
| 試算表或報表 | 指標定義、編輯者、更新頻率與公式基礎 |
| 專家經驗 | 使用條件、例外、佐證證據，以及能否成為明確規則 |
| 外部知識 | 來源、發布日期、授權，以及與內部規則衝突時的優先順序 |

**建議：**不要將未經驗證的訪談內容直接轉換為可自動執行的動作規則。在可追責的業務負責人驗證前，將其標示為候選知識。

## 血緣與證據

圖表明確包含權限與血緣。使用者應能追溯任何答案、指標或動作：

```text
來源系統／文件 → 擷取時間 → 清理與轉換規則 → 本體資產版本
→ 應用程式或代理使用紀錄 → 輸出或回寫結果
```

這條鏈可支援資料爭議處理、合規審查與結果調查。

## 待釐清問題

1. 第一批要擷取的來源是哪些？各來源由誰負責？
2. 哪些資料或文件包含個人、機密或受限制資訊？
3. 在資產提供應用程式使用之前，應採用何種品質閘門、審查頻率與例外處理程序？
