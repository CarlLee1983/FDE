## 圖表定義

企業本體層是「單一語意事實來源」，包含下列元素。

| 元素 | 圖表範例 | 用途 |
| --- | --- | --- |
| 物件 | 客戶、訂單、設備、工單 | 表示業務實體 |
| 關係 | 客戶—訂單—生產線—供應商 | 表示實體之間的業務連結 |
| 動作 | 核准、派工、回寫至系統 | 表示可執行或記錄的動作 |
| 權限與血緣 | 權限、負責人、資料來源 | 使資產可治理且可稽核 |

## 為何本體是語意邊界，而非資料庫綱要

資料庫綱要服務於儲存與交易；本體服務於業務意義與跨系統關係。同一位客戶可能出現在 CRM、ERP、服務日誌與文件中。本體定義這些紀錄何時代表同一位客戶、哪個來源具權威性、誰可以存取，以及它如何連結訂單或工單。

來源系統的結構可以改變。客戶、訂單與派工等穩定的企業概念，應在這些改變之中仍保持可理解與可治理。

## 最小可行模型

**建議：**從單一情境所需、最小且完整的集合開始，而非從完整企業模型開始。

```text
物件：Customer、Order、Work Order、Equipment
關係：Customer 擁有 Order；Order 觸發 Work Order；Work Order 使用 Equipment
動作：查詢 Order、建立 Work Order、派工、核准、回寫
```

每個元素都應回答一個業務問題或支援一項動作。暫緩處理目前沒有使用方的元素。

## 資產規格

### 物件

| 欄位 | 說明 |
| --- | --- |
| 名稱與業務定義 | 平易近人的範圍說明與明確排除項目 |
| 識別規則 | 唯一鍵、跨系統對應與去重規則 |
| 關鍵屬性 | 情境所需的狀態、時間、金額或分類資料 |
| 權威來源 | 擁有最終寫入權限的系統或流程 |
| 品質規則 | 完整性、有效性、即時性與例外處理 |

### 關係

| 欄位 | 說明 |
| --- | --- |
| 關係名稱 | 業務動詞，例如「Customer places Order」 |
| 起點與終點 | 連結的兩種物件類型 |
| 基數與有效性 | 一對一、一對多或多對多，以及生效日期 |
| 證據來源 | 系統、文件或人工確認來源 |
| 約束 | 無效組合、先決條件與例外 |

### 動作

| 欄位 | 說明 |
| --- | --- |
| 動作名稱與意圖 | 例如派工會建立可追責的指派 |
| 觸發者 | 人員、系統、工作流程或代理 |
| 輸入與先決條件 | 必要物件、權限、狀態與核准條件 |
| 效果 | 建立、變更、通知或回寫的紀錄 |
| 稽核紀錄 | 呼叫者、時間、輸入、輸出、結果與失敗原因 |

## 版本管理與相容性

圖表包含版本管理與回復。**建議：**將本體定義視為具版本的資產：提出並界定變更範圍、在影子環境測試、取得負責人核准，然後在已知的回復點發布。訂單狀態或客戶定義的變更，可能需要重新驗證每個相依的儀表板、代理與工作流程。

## 待釐清問題

1. 第一個情境不可或缺的物件、關係與動作是哪些？
2. 核心物件的權威來源與識別規則是什麼？
3. 是否已有可作為初始證據的資料字典、主檔資料或流程定義？
