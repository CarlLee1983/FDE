# 09｜FED 情境至動作方法

專案層級的 [FED 情境至動作方法](../../FED-Scenario-to-Action-Method.md)，是將業務情境轉化為受治理 FED 能力的工作方法論。

## 為何需要方法包

FDE 架構描述了層次與交付流程，但本身並未規定如何分析問題、區分流程與決策邏輯、治理語意資產，或評估自動化風險。因此，FED 採用由既有系統分析方法組成的輕量方法包。

| FED 關切面向 | 所用方法 | 成果 |
| --- | --- | --- |
| 有邊界的業務成果 | 需求工程 | 已核准的情境與驗收條件 |
| 流程與例外工作 | BPMN / CMMN | 含特定介入節點的流程或案例模型 |
| 實體、關係與生命週期 | UML 結構／狀態建模 | 分離的結構與狀態定義 |
| 可重用語意與來源對應 | ISO/IEC 11179 登錄模式 | 具身分與血緣、受治理的語意資產 |
| 決策或規則邏輯 | DMN | 具名、可測試的決策服務 |
| 存取、動作與監控 | NIST RMF | 與風險相稱的控制與授權證據 |
| 架構權衡 | SEI ATAM | 品質情境與明確接受的風險 |
| 迭代驗證 | ISO/IEC/IEEE 15288 | 小型垂直切片與回饋迴圈 |

官方來源研究、直接連結，以及此綜整的界限，記錄於[可提供 FED 參考的系統分析方法](../research/system-analysis-methods.md)。

## 形成的 FED 方法

```text
界定 → 繪製工作 → 建模意義 → 明確決策 → 確保控制 → 證明並演進
```

此方法可防止常見失敗模式：

- 在定義營運成果前就建置代理；
- 將工作流程視為業務意義的唯一表述；
- 把政策決策隱藏在提示詞或 UI 行為中；
- 在證據、存取與復原尚不可信前就啟用回寫；
- 未具備回饋、責任歸屬與重用，就將已交付能力視為完成。

準備第一個真實 FED 情境時，請使用完整的[方法文件](../../FED-Scenario-to-Action-Method.md)。
