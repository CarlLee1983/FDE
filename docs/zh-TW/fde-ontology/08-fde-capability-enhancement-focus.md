## 專案定位

FDE 能力強化是本專案的目的。本體驅動的 FDE 架構仍是參考模型：它有助於辨識 FDE 能建置與強化的項目，但不預設其為本專案現有的實作或完整產品定義。

實務問題不是「如何重建這張圖？」而是「哪些能力能讓 FDE 在真實業務情境中交付可信、受治理且可重用的成果？」

## 能力優先序

| 優先級 | 能力 | 現在優先的原因 |
| --- | --- | --- |
| P0 | 情境登錄 | 在選擇技術前，建立可衡量目的與責任歸屬人 |
| P1 | 本體資產生命週期 | 避免每項 FDE 功能各自定義業務術語 |
| P1 | 證據感知的脈絡解析 | 使答案與指標可歸因於獲准使用的來源 |
| P2 | 決策支援 | 將脈絡轉化為營運儀表板或代理互動 |
| P3 | 受控動作執行 | 僅在唯讀與建議型使用獲得信任後，才加入營運影響 |
| P4 | 跨情境重用與治理 | 將交付工作轉化為可累積的 FDE 能力 |

P0 與 P1 應構成第一個垂直切片。P2 與 P3 不應被視為獨立產品：它們取用相同的情境、語意資產、脈絡與存取決策。

## 第一份可建置契約

本專案現已包含 FDE 情境紀錄的 JSON Schema：[schemas/fde-scenario.schema.json](../../../schemas/fde-scenario.schema.json)。此 Schema 與技術無關，並確立 FDE 在建置情境前必須蒐集的資訊：

| 契約元素 | 所啟用的能力 |
| --- | --- |
| 責任歸屬人 | 定義核准、持續決策與驗收 |
| 流程節點與使用者角色 | 狹窄且可測試的營運範圍 |
| 決策或動作 | 從資訊直接通往工作 |
| 基準與目標指標 | 以成果衡量，而非展示評估 |
| 本體參照 | 建置或擴充所需的最小共享語意 |
| 來源參照 | 權限、新鮮度與血緣決策 |
| 驗收條件 | 可驗證的發布決策 |

隨附的[示例紀錄](../../../examples/order-exception-triage.scenario.json)刻意保持通用。它僅展示契約形狀；在開始實作前，必須以 FDE 第一個真實情境取代。

## 填妥契約後要開發的模組

以下模組依相依關係排序。介面應維持精簡，實作則吸收反覆出現的複雜度。

| 模組 | 介面目的 | 模組內部保留的複雜度 |
| --- | --- | --- |
| 情境登錄模組 | 登錄並解析已核准情境 | 驗證、責任歸屬檢查、指標中繼資料、生命週期狀態 |
| 本體資產模組 | 讀取已發布定義並治理定義變更 | 版本管理、檢視、影響分析、淘汰 |
| 脈絡解析模組 | 回傳情境請求所允許且有來源的脈絡 | 來源介接器、對應、品質檢查、存取評估、血緣 |
| 決策支援模組 | 從脈絡產出指標、答案或建議 | 計算、模型使用、格式化、不確定性處理 |
| 動作執行模組 | 準備、核准並執行具名動作 | 前置條件、冪等性、稽核、重試、復原 |

## 下一個驗收目標

立即目標不是自主動作，而是針對一個已核准情境完成一項唯讀查詢，並回傳：

```text
結果 + 語意定義版本 + 來源證據 + 新鮮度狀態 + 存取決策
```

此結果是 FDE 能向使用者提供以受治理企業脈絡為基礎之答案的第一項證明。一旦它可靠，相同脈絡即可驅動儀表板、決策支援互動，最終也能驅動受控動作。
