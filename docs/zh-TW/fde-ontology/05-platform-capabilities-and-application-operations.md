## 圖表定義

平台基礎包含四項能力：資料治理與即時同步、模型與代理編排、權限治理與稽核，以及版本管理與回復。它支援企業本體與 FDE 交付引擎，但不取代兩者。

## 能力拆解

| 能力 | 要解決的問題 | 最低可驗證成果 |
| --- | --- | --- |
| 資料治理與同步 | 應用程式使用過時、不正確或不可追溯的資料 | 可觀測的同步狀態、來源與新鮮度 |
| 模型與代理編排 | 模型、提示詞、工具與任務流程分散 | 可設定的代理任務、工具邊界與執行紀錄 |
| 存取控制與稽核 | 使用者或代理存取超出職責範圍的資料／動作 | 可查詢的身分、資產、動作與稽核紀錄 |
| 版本管理與回復 | 本體或應用程式的變更中斷營運 | 可識別版本、可比較變更，以及已知良好的回復點 |

## 應用形式與控制邊界

| 應用形式 | 典型用途 | 要控制的風險 |
| --- | --- | --- |
| 儀表板 | 呈現營運與管理指標 | 定義一致性、新鮮度與向下追溯來源 |
| 代理 | 查詢、摘要、推理或提出建議 | 工具權限、來源脈絡、無根據的主張與無法解釋的建議 |
| 工作流程 | 指派、核准、通知或寫入系統 | 前置條件、人工核准、冪等性與失敗補償 |

圖表納入核准、派送與系統回寫動作。**建議：**採用三層權限：唯讀查詢、提出建議與受控執行。動作越接近對外部或持久性資料造成影響，所需的核准與稽核就應越嚴格。

## 典型執行路徑

```text
使用者或工作流程觸發
→ 取得已獲允許的本體脈絡與資料
→ 代理／規則／工作流程評估請求
→ 顯示結果、提出動作，或請求核准
→ 執行受控動作
→ 記錄輸入、證據、輸出與結果
→ 回寫業務系統，並更新相關本體狀態
```

發生失敗時，負責營運的人員需要有足夠證據，能區分資料、規則、系統或存取問題，並執行補償或回復。

## 介面原則

**建議：**應用程式應透過本體邊界取用業務物件、連結與動作，而非直接相依於來源系統的內部欄位名稱。如此可將來源系統變更侷限在連接與對應層，並減少連鎖的應用程式修改。

## 待釐清問題

1. 現在有哪些系統可讀取？哪些系統允許回寫？
2. 是否已有可重用的身分識別、授權、稽核或工作流程平台？
3. 哪些高影響動作需要人工核准或雙重控制？
