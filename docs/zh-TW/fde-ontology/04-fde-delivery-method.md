## 圖表定義

圖表為 FDE 小隊配置三項能力：業務轉譯者、資料／本體工程師與應用交付工程師。其交付引擎遵循五個階段：現場診斷、本體建模、應用組裝、與定義對齊的平行運作，以及移交／資產化。

## 角色協作

| 角色 | 業務責任 | 交付產物責任 |
| --- | --- | --- |
| 業務轉譯者 | 對齊需求、術語、流程與指標 | 情境定義、驗收標準、SOP 協作 |
| 資料／本體工程師 | 驗證資料可用性與業務語意 | 物件、關係、動作、血緣與品質規則 |
| 應用交付工程師 | 促進在營運工作流程中的採用 | 儀表板、代理、工作流程、上線與訓練 |

這些角色共同協作，而非彼此孤立地交接工作。模型必須立足於現場；應用程式必須理解語意定義與存取限制。

## 五階段分析

### 1. 現場診斷

找出造成損失或風險的流程節點、做出決策的角色、所需資料與規則，以及可衡量的成功條件。產出包括情境敘述、流程圖、資料／知識需求與基準指標。

### 2. 本體建模

將診斷結果對應至物件、關係、動作與治理中繼資料。除了順利路徑，還要建模例外路徑、狀態轉換、權威來源與存取規則。

### 3. 應用組裝

建立所需的儀表板、代理或工作流程。儀表板支援觀察；代理支援擷取、推理與建議；工作流程執行受控步驟與系統回寫。每項輸出都應標示其語意與來源依據。

### 4. 影子運作

圖表明確要求新舊作業平行運作並對齊定義。在既有流程仍具權威性時，新能力可產生結果或建議。在擴大權限前，應比較差異、錯誤來源、例外與人工介入成本。

### 5. 移交與資產化

移交內容包括 SOP、訓練與可追責的負責人。**建議：**亦應納入資產清單、例外處理程序、變更流程、監控檢查清單與復原路徑。

**證據狀態。** 本階段由使用者提供的架構圖導出，屬本專案的綜整。[FDE 一手來源紀錄](../research/forward-deployed-engineer-sources.md)所讀過的一手來源，沒有任何一份載明此角色的退場或交接條件，因此此處內容不得被引用為業界既定作法。

## 建議的驗收閘門

| 閘門 | 驗收問題 |
| --- | --- |
| 業務價值 | 已定義的指標是否以可重現的方式改善？ |
| 語意正確性 | 使用者是否接受物件、關係、狀態與指標定義？ |
| 資料品質 | 關鍵紀錄是否具有已知來源、即時性與例外處理？ |
| 營運安全性 | 寫入或派工動作是否具有適當權限、核准與稽核？ |
| 可維護性 | 可追責的負責人能否管理變更、事件處理與回復？ |

## 待釐清問題

1. 誰組成第一個 FDE 小隊？誰是業務決策者？
2. 影子運作應持續多久？何種條件構成通過？
3. 哪些動作維持建議性、哪些需要核准，以及哪些可自動回寫？
