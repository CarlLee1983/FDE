# Source map

This Skill carries the local references required to run its analysis, proposal, scenario-preparation, delivery, and assurance branches. Read only the source needed by the active branch. These packaged snapshots define this Skill's guidance; they do not make the target repository's similarly named files FDE sources.

| Need | Packaged source and heading | Use |
| --- | --- | --- |
| Project language and boundary | [CONTEXT.md](canonical/CONTEXT.md) and [accepted ADRs](canonical/adr/) | Confirm the five-capability boundary without reading the target repository's files. |
| Capability set and validation | [FDE-Capability-Enhancement-Plan.md](canonical/FDE-Capability-Enhancement-Plan.md) — `Capability Target`, `Default Case Output`, `Case-Based Validation` | Understand the five analysis capabilities and their quality criteria. |
| Full-depth method and conditional gates | [FDE-Scenario-to-Action-Method.md](canonical/FDE-Scenario-to-Action-Method.md) — `Collaborative Clarification`, `Optional Six-Stage Reference Flow`, `Full-Depth Artefact Set`, `Conditional Assurance Gates` | Deepen analysis, prepare formal artefacts, or assess authority only when the case requires it. |
| Collaborative-clarification output | [collaborative-clarification.md](collaborative-clarification.md) | Resolve decision dependencies with accountable participants before a scenario or solution relies on them. |
| Scenario contract | [packaged schema](../schemas/fde-scenario.schema.json) — schema root `FDE Scenario Record` | Validate required fields, field constraints, and closed-object rules directly from the packaged schema. |
| Scenario validation | [scripts/validate-scenario.sh](../scripts/validate-scenario.sh) | Run deterministic metaschema and scenario-record validation after creating or changing a scenario. |
| Scenario shape | [scenario example](canonical/schemas/fde-scenario.example.json) | Inspect record shape; do not reuse its facts as target-enterprise evidence. |
| Capability seams, ownership, and promotion | [capability map and implementation strategy](canonical/docs/fde-ontology/07-capability-map-and-implementation-strategy.md) — `Capability Map`, `Recommended Delivery Sequence`, `Module Seams and Ownership`, `Capability Ownership and Return`, `Validation Strategy`, `Decisions Needed Before Implementation` | Design or build the smallest governed slice, keep domain behaviour case-owned, and assess cross-scenario promotion without treating proposals as current implementation facts. |
| Capability-return output | [capability-return-review.md](capability-return-review.md) | Classify learning after a case slice reveals a possible reusable capability or FDE-core change. |
| Project-specific application of the reference model | [capability enhancement focus](canonical/docs/fde-ontology/08-fde-capability-enhancement-focus.md) — `Project Positioning`, `Closed Project Capability Set`, `Conditional Solution Patterns` | Separate analysis capability from solution-pattern and implementation assumptions. |
| Application authority tiers | [platform capabilities and application operations](canonical/docs/fde-ontology/05-platform-capabilities-and-application-operations.md) — `Application Forms and Control Boundaries` | Distinguish read-only query, recommendation, and controlled execution as design tiers; verify actual permissions from target-enterprise evidence. |

The package manifest, [packaged-sources.json](packaged-sources.json), records every canonical source snapshot. FDE maintainers regenerate them with `python3 scripts/sync-skill-references.py` and verify them with `python3 scripts/sync-skill-references.py --check`.

Large synthetic examples, translations, and method rationale are optional supplementary reading, not execution dependencies. When needed, use the fixed `v0.2.1` sources: [method rationale](https://github.com/CarlLee1983/FDE/blob/v0.2.1/docs/fde-ontology/09-fde-scenario-to-action-method.md), [shipment-delay example](https://github.com/CarlLee1983/FDE/tree/v0.2.1/examples/shipment-delay-priority), [governed-evolution example](https://github.com/CarlLee1983/FDE/tree/v0.2.1/examples/decision-memory-evolution), and [Traditional Chinese translations](https://github.com/CarlLee1983/FDE/tree/v0.2.1/docs/zh-TW). They are never required to analyse, validate, or deliver from the installed Skill.
