# 個人 Email 管理：從收件匣雜訊到每日行動清單

> **Synthetic demo only。** 本案例的信件、人物、數字、資料來源、權限與成果皆為虛構，只用來示範 FDE 方法；它不代表任何信箱已授權連線或任何成效已獲證實。

這個案例把 FDE 方法放進日常生活：一個人的工作信、帳務通知、收據、電子報與私人往來都進入同一個收件匣。真正困難的不是「信太多」，而是每封信都要求人重新判斷：需要我做什麼、何時以前要做、是否該回覆，以及能不能放心略過。

## 一分鐘理解

第一步不做自動回信，也不讓 AI 接管信箱。先建立一份「信箱唯讀」的每日審閱清單，用確定性規則整理討論串、寄件者、收件方式、未讀狀態與信件時間。若要保存使用者的「需處理、等待中、參考、略過」與理由，這是另一個受控寫入，必須有獨立授權、稽核與保留政策。

等流程、隱私範圍與 baseline 被使用者確認後，再用同一批信件做 AI shadow，比較 AI 是否能更準確地摘要討論串、抽取下一步與期限、以及準備回覆草稿。AI 只能提出建議；寄送、刪除、封存與退訂都不在第一階段權限內。

## 最小責任邊界

| 工作 | 負責者 |
| --- | --- |
| 讀取授權、信件取得、討論串合併、新鮮度與規則分組 | 確定性軟體（信箱唯讀） |
| 保存使用者的審閱決定 | 另行授權、可稽核、冪等且可移除的 decision store |
| 摘要、行動與期限候選、回覆草稿 | AI（僅限 readiness 後的 shadow 候選） |
| 判斷重要性、確認待辦、接受或修改草稿 | 信箱使用者 |
| 寄送、刪除、封存、退訂 | 明確授權且可稽核的系統行動；第一切片不包含 |

## 證據狀態

案例目前為 `proposed`，AI selection 為 `deferred`。真實信箱權限、敏感內容邊界、現況流程、使用者接受、baseline 與目標都是 `missing` 或 `unverifiable`。因此它可以用來演練與製作合成原型，不能直接連接真實信箱或宣稱能節省時間。

## 第一個真實工作包

由一位自願使用者選定一個受控資料範圍（優先使用去識別或合成信件），確認哪些信件類型永不進入處理範圍，並完成一週人工 baseline。接著以唯讀模式產生每日審閱清單，量測是否漏掉行動信件，以及整理是否真的減少重複掃描。
