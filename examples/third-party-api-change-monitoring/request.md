# Third-party API change monitoring reference request

Create a generic FDE example for a team that integrates with three external services and currently relies on engineers to notice API version changes through passive, manual checks.

The example should redesign the operating workflow before selecting technology. Its first slice must remain read-only and operate in shadow mode: collect only approved official vendor sources, detect stable version and contract changes deterministically, use AI only for source-grounded interpretation of unstructured release notes and internal usage context, and route every impact or upgrade decision to an accountable human.

This repository request establishes only a proposed reference shape. The actual vendors, source authority, access terms, current check effort, internal dependency inventory, ownership, notification channel, baseline, target, and acceptance evidence remain `missing` or `unverifiable`.
