# FDE Operating Analysis

This context defines the analysis-and-assistance capability that the project strengthens in an FDE. The project helps shape operating work; it is not an enterprise application platform.

## Language

**FDE (Forward Deployed Engineer)**:
An engineer embedded in a concrete business setting who translates operating problems into working, governed capabilities.
_Avoid_: alternative acronyms or expanding FDE as an engineering discipline

**FDE capability**:
The ability to turn an operating problem into a workflow-informed, evidence-bounded recommendation and next accountable action.
_Avoid_: enterprise software module, runnable demo, one-off AI answer

**FDE operating-analysis skill**:
A reusable method for clarifying an operating scenario, diagnosing and redesigning its workflow, selecting the simplest sufficient intervention, and forming an actionable recommendation.
_Avoid_: application builder, delivery toolkit, enterprise platform

**Target operating capability**:
The scenario-specific way of working that an FDE may help an organization shape or improve. It belongs to the target operation, not to this project.
_Avoid_: FDE skill, project module

**Validation artefact**:
An optional scenario record, model, schema, replay, or executable example used to test an analysis claim when evidence is needed. It supports the analysis and is not the default project outcome.
_Avoid_: product feature, maturity milestone, required implementation

**Operating solution**:
An actionable account of the bounded problem, current-work diagnosis, redesigned workflow, intervention choice, evidence limits, and next accountable action.
_Avoid_: artefact inventory, implementation backlog, application

**Delivery decision**:
The evidence-bounded choice of what should happen next, including whether to implement, validate, defer, or stop. Implementation begins only when separately requested.
_Avoid_: automatic handoff to coding, release approval

**Case**:
A bounded example used to teach, stress-test, or validate the analysis method. Case-specific behavior remains with the case unless repeated independent evidence justifies changing the core skill.
_Avoid_: product module, automatic core capability

**Core analysis flow**:
The minimum reasoning sequence: frame the operating problem, diagnose and redesign the workflow, select the simplest sufficient intervention, and form an operating solution. Deeper models and gates are used only when the case needs them.
_Avoid_: mandatory artefact checklist, unrestricted analysis

**Intervention**:
A deliberate change to process, responsibility, information, deterministic software, human judgment, AI assistance, or governed action selected to improve the target workflow.
_Avoid_: AI feature, implementation by default

**Core intervention principle**:
**穩定規則交給軟體，語言負擔才考慮 AI。** Assign stable rules, calculations, controls, and repeatable state transitions to deterministic software. Consider AI only for retained work whose material burden comes from language interpretation, synthesis, explanation, or bounded reasoning, and only when evidence shows value over the non-AI workflow. Persistent effects remain human-governed or explicitly authorized.
_Avoid_: using AI to compensate for unclear ownership, broken process, inconsistent data, or unspecified policy

**Reference hypothesis**:
An explicit, testable assumption used to analyse a generic case when target-enterprise evidence is unavailable. It demonstrates reasoning but does not establish enterprise fact, acceptance, authority, or value.
_Avoid_: verified fact, fictional approval

**Analysis completion**:
The point at which a user can decide the next action from a bounded problem, current-work diagnosis, target workflow, intervention rationale, explicit evidence limits, and accountable next step.
_Avoid_: enterprise acceptance, gate passage, implementation completion

**Assurance gate**:
A conditional check that restricts authority or claims when real access, release, persistent action, or value is at stake. It is not a default progress measure for case analysis.
_Avoid_: analysis stage, case score, universal checklist

**Solution pattern**:
A reusable way to reason about a possible operating solution, such as scenario registration, semantic definition, context resolution, decision support, or controlled action. A pattern is selected only when a case needs it and is not a project module to build by default.
_Avoid_: roadmap commitment, core product capability

## Capability Set

**Operating problem framing**:
The capability to turn a vague request into a bounded operating problem with a relevant user, workflow location, outcome, and decision.

**Workflow diagnosis and redesign**:
The capability to explain current normal, exception, escalation, and rework paths and propose a simpler technology-neutral target workflow.

**Intervention selection and AI-fit**:
The capability to compare process, responsibility, information, deterministic software, human judgment, AI assistance, and governed action and select the simplest sufficient intervention.

**Operating solution formation**:
The capability to combine the diagnosis, target workflow, intervention rationale, evidence limits, and next accountable action into a usable decision.

**Optional delivery and assurance assistance**:
The capability to help plan, review, validate, or hand off implementation only when separately requested.
_Avoid_: automatic implementation after analysis

## Quality

**Minimum operating solution**:
The default five-part answer: operating problem and outcome, current-work diagnosis, target workflow, intervention and AI-fit decision with evidence limits, and next accountable action.
_Avoid_: fixed document bundle, mandatory implementation plan

**Sufficient depth**:
The least analysis detail that supports a sound next decision. Additional models, assurance, research, or executable validation are justified only by material uncertainty, risk, authority, persistence, or an explicit request.
_Avoid_: maximum detail by default, shallow answer regardless of risk

**Case evaluation**:
An assessment of whether the skill bounded the problem, understood the whole workflow, redesigned work before technology, selected an appropriate intervention, preserved evidence boundaries, and enabled a next action across varied domains.
_Avoid_: file count, code volume, number of runnable examples
