專案目的

此專案用來強化 FED 的能力。FDE 本體論驅動交付架構是參考模型，而非 FED 的既定實作或完整產品定義。

共用語義

讓物件、關係、行動與指標在不同應用中使用一致定義。

具證據的上下文

讓結果能指出資料來源、版本、新鮮度與存取決策。

決策支援

先讓看板與 Agent 提供可理解、可驗證的答案與建議。

受控行動

僅在權限、核准、稽核、冪等與復原條件完備後才允許回寫。

核心原則：先證明唯讀結果的語義一致性、來源血緣與存取控制，再逐步提高自動化與寫入權限。

能力路線圖

FED 的目標不是累積孤立功能，而是由一個情境開始，逐步將可重用能力沉澱為企業資產。

成熟度能力完成定義
1. 已定義情境登錄有負責人、決策、來源集合與可量測結果。
2. 有依據語義上下文已授權請求可解析為具版本的物件、關係、資料與血緣。
3. 有用決策支援看板或 Agent 使用相同上下文，並符合業務定義。
4. 受控行動執行已核准行動符合前置條件、保留稽核軌跡並具失敗處理。
5. 可累積重用與治理第二個情境重用資產，而非建立競爭性定義。

第一個可實作能力

情境登錄是一份技術中立的契約。它先將產品意圖、營運責任、本體範圍、資料來源與驗收證據連結起來，讓實作不會從「做一個 Agent」這種無邊界的請求開始。

FED 情境至行動方法

此方法輕量整合需求工程、BPMN／CMMN、UML、ISO 11179、DMN、NIST RMF、ATAM 與 ISO 15288；它們各自處理不同問題，不相互取代。

01界定確認業務成果、範圍、負責人與驗收條件。
02描繪工作標示正常、例外、升級路徑與介入節點。
03建模意義區分物件關係、生命週期狀態與語義登錄。
04明確決策將重要規則與建議寫成可測試的決策服務。
05確保控制設定權限、風險控制、品質取捨與復原需求。
06證明與演化以最小垂直切片和影子運行驗證，再將回饋沉澱。

六個問題，一條可追溯鏈

  1. 哪個營運成果與決策重要？
  2. 該決策在流程或案例的何處發生？
  3. 哪些業務事實、狀態與關係使結果成立？
  4. 哪些來源證據與語義定義支撐它？
  5. 哪些決策邏輯、風險控制與品質取捨限制它？
  6. 如何在增加權限前證明它有價值？

決策關卡

關卡是避免跳過必要分析的節奏控制，而非大型瀑布式流程。

G1 — 情境核准
成果有邊界、負責人且可量測，才開始建模。
G2 — 語義落地
事實、狀態、指標、來源與負責人已定義，才建置唯讀上下文。
G3 — 證據已證明
使用者可取得已授權、新鮮且可說明的結果，才進入決策支援。
G4 — 決策已受控
具影響性的邏輯可測試且受治理，才啟用核准工作流。
G5 — 行動已授權
權限、核准、稽核、冪等與復原均經測試，才允許受控回寫。
G6 — 價值已證明
生產或影子證據符合驗收條件，才擴大到相鄰情境。

第一條能力切片

第一個目標不是自主行動，而是單一核准情境中的唯讀、可解釋查詢。

結果 + 語義定義版本 + 來源證據 + 新鮮度狀態 + 存取決策

這是 FED 能提供受治理企業上下文的第一個證明。可靠後，同一份上下文可被看板、決策支援互動，以及後續受控行動重用。

接下來的工作坊

  1. 情境界定：確認業務負責人、使用者、基線、目標與驗收。
  2. 工作與意義：確認流程／案例、介入節點與最小語義資產集合。
  3. 決策與控制：確認決策服務、風險控制、品質情境與首切片測試。
