FDE operating-analysis skill

先把工作弄順，再選工具。

本專案協助 FDE 把有邊界的營運問題，轉成受證據限制的營運方案與下一個有責任歸屬的行動。它不是 Agent、產品、企業平台或預設 implementation roadmap。

五分鐘開始使用 閱讀繁中 README

預設只需要五個部分

  1. 營運問題與預期結果。
  2. 現行工作的診斷。
  3. 技術中立的目標工作流程。
  4. 介入方式、AI 適用性與證據限制。
  5. 下一個有責任歸屬的行動。

這五段足以讓使用者決定下一步時，分析就完成了；不必為了看起來完整而先建立 schema、model、gate 或程式。

介入原則

穩定規則交給軟體，語言負擔才考慮 AI。

先重整工作刪除、簡化、標準化、重新分工，並修好定義與資訊流。
再選最小充分介入比較流程、責任、資訊修復、確定性軟體、介面支援、人工判斷與 AI。
AI 是條件式選項只處理保留下來的語言理解、整合、說明或有限推理負擔，並需證據支持。
不需要 AI 也是完整決策固定轉換、計算、權限與狀態轉換優先交給可測試的軟體。

Models 與企業架構不是 roadmap

情境登錄、語義定義、上下文解析、決策支援與受控行動是案例有需要時才選用的 solution patterns。Schemas、models、assurance、implementation 與企業平台架構都是 supporting references 或條件式深度，不是本專案必建模組。

安全安裝，同一條驗證鏈

安裝scripts/install-skill.sh --target /path/to/project --agent both 只建立 Skill 目錄，預設拒絕覆寫。
驗證make verify 是本地與 Pull Request 共用的 frozen verification entry point。

證據邊界

Repository tests、scenario schema validation 與 Pages checks 只證明 repository behavior。Supporting documents 與合成案例不得被解讀為任何企業的 acceptance、access、authority、production readiness 或 business value。

英文 README.md 是維護中的 canonical entry；繁中內容是對齊閱讀版。
